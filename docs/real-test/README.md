# 真机实测记录（2026-10-23）

我在一台 Windows 10（19044）电脑上实测了 v1.1.0 图形界面版，OfficePLUS 版本 3.10.0.28331。

- **Office 自动装上的 OfficePLUS**：扫描出 15 处残留（1 个进程、1 个服务、10 个注册表项、3 个目录），一键清理后复扫为 0，日志里没有失败记录。
- **从 OfficePLUS 官网下载安装包装的**：扫描出 14 处残留，同样清理干净。

这个文件夹里是第一次清理留下的原始文件（只把 `.reg` 改成了 UTF-8 的 `.reg.txt`，避免被误双击导入、也方便在 GitHub 上直接看）：

| 文件 | 内容 |
| :--- | :--- |
| `清理日志_20261023_152244.txt` | 这次清理每一步做了什么 |
| `OfficePLUS_注册表备份_20261023_152243.reg.txt` | 清理前自动导出的 10 个注册表项，也就是 OfficePLUS 真实写入的位置和内容 |

CI 会用 `tests/real_sample_check.py` 核对这两个文件：里面出现的每个注册表项、进程、服务和目录，`rules.json` 都必须能识别。改规则时如果漏掉了真实存在的项，CI 会失败。

注意：日志里有一行「已结束进程: EXCEL.EXE」。清理时会强制关闭 Word、Excel、PowerPoint、Outlook，才能删掉被占用的加载项文件，所以清理前请先保存文档。
